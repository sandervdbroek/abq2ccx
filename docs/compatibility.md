# Compatibility

The facts about Abaqus and CalculiX that the converter relies on, and where each comes from.
Each was taken from a primary source — the CalculiX manual or sources, the Abaqus manuals —
and the behavioural ones were **probed** on ccx 2.23 (the FreeCAD 1.1.4 build): small decks
run against a hand calculation or an equivalent model. `validate_with_ccx.py` repeats many
of the probes on the bundled examples ([testing](testing.md#2-end-to-end--validate_with_ccxpy)).

## Syntax and mesh

| Fact | What the converter does | Evidence |
| --- | --- | --- |
| Solid and shell node ordering is the same in both codes (C3D20, C3D10, C3D15, C3D6, S8R, S6) | passes connectivity through | ccx manual ("compatibility with ABAQUS"); `gmsh2ccx`; the LE10 benchmark |
| Solid face numbering is the same | passes `P1..P6` and `S1..S6` through | the two codes' face tables |
| ccx has no mesh-generation cards and no `*PART`/`*INSTANCE`/`*ASSEMBLY`/`*SYSTEM` | expands the cards; flattens to one numbering | ccx keyword set |
| `*INSTANCE` applies the translation before the rotation | flattens as R(p + T) | Abaqus Keywords manual; `validate_with_ccx.py assembly_rotated_instances` (a turned instance solves exactly like the model written flat) |
| A part's `*ORIENTATION` is rotated with each instance; `DEFINITION=NODES` names the part's nodes, and without node c a rectangular system's origin is the part's | gives each instance's copy that instance's nodes; without node c, a moved instance's a and b are the part's node positions turned | Abaqus 2017 "Orientations", Keywords `*ORIENTATION`; `validate_with_ccx.py assembly_rotated_instances_nodes`, `_nodes_no_c` |
| `*NODE, SYSTEM=C` gives R, θ, Z and `SYSTEM=S` R, θ, φ (degrees; θ about Z from X, φ up from the X-Y plane), and a normal on such a line is given in the same form (its second entry an angle, in `SYSTEM=S` its third too); the normal on a `*NODE` line is used for every conventional shell element at the node | converts the coordinates and those normals before flattening; writes the normals as `*NORMAL` lines per shell element (ccx would average the element normals) | Abaqus 2017 Keywords `*NODE`; "Node definition"; "Defining the initial geometry of conventional shell elements" |
| `*NFILL` with bounding sets of different lengths ignores the longer set's extra nodes | does the same | Abaqus 2017 "Node definition" |
| ccx accepts set and surface names up to 80 characters | keeps flattened names within 80, unique | probed (longer: "set name too long") |
| ccx reads only the first 20 characters of a numeric field, without an error when the cut is still a number (`6.000000000000000E-01` → 6) | writes at most 12 significant digits | probed |
| Abaqus reads a blank data field as zero unless the field has a default (no `*DLOAD` or `*DSLOAD` field has one); ccx 2.23 reads a blank `*DLOAD` field as zero too, so a dropped one moves the fields after it one place up | keeps every `*DLOAD` and `*DSLOAD` field in its place, a blank number written `0.` | Abaqus "Input syntax rules", Keywords manual (`*DLOAD`, `*DSLOAD`); sources `splitline.f`, `dloads.f`; probed (`EALL, GRAV, 9810., , , -1.` without its blanks pulls a column along −x; a `CENTRIF` line without its blank axis point has an axis of length zero: NaN) |
| A keyword line ending in a comma continues its parameters on the next line | splices them; never merges a data line | Abaqus input syntax |
| Coupled temperature–displacement elements have the base element's name in ccx (`C3D8T` ≡ `C3D8`); the step supplies the temperature DOF | strips the `T` | ccx element sections |
| `NSET=` on `*NODE`, `ELSET=` on `*ELEMENT`, `GENERATE` on sets are accepted; an `*NSET` built from an `ELSET` is not | uses the first; expands the second | ccx manual |

## Elements and sections

| Fact | What the converter does | Evidence |
| --- | --- | --- |

| A composite ply line without an orientation takes the previous line's orientation in ccx 2.23 (a [0/90/0] plate runs as [0/90/90]) | names the global axes (`ABQ2CCX_OR0`) on such plies when another ply has an orientation | probed (plate deflection 2× CLT's; membrane tests) |
| Abaqus projects a shell or membrane orientation onto the element — the axis that follows the rotation axis, whose default 1 "should have a nonzero component in the direction of the normal" — then turns a layer about the normal; ccx 2.23 turns an orientation about its own axis and projects the turned axis 1 onto a shell (axis 3 where axis 1 is the normal), but gives a membrane the turned axes unprojected (the global axes without an orientation) | keeps the cards where the two agree; elsewhere (another plane, a reversed normal, a curved shell, a rotation about axis 1 or 2, a cylindrical system on a cylinder, a spherical system, which ccx lacks, a membrane off the global axes, a `*DISTRIBUTION` whose axis 3 is not the normal) gives each element group of an orthotropic or anisotropic section its directions in the element's plane, plies included; computes the ply axes of split continuum shells by Abaqus' rule; without a rotation line turns about axis 1, Abaqus' default ("will by default use the local 1-axis"), warned where that axis lies in the shell | Abaqus 2017 "Orientations", Keywords `*ORIENTATION`; probed on `S3`–`S8R` and `M3D3`/`M3D4`/`M3D4R` (an x-z laminate: A 185 % off before; a hoop-wound cylinder 14× too soft); `validate_with_ccx.py shell_axes_*`, `cylinder_hoop`, `sphere_hoop_*`, `distribution_panel_*` |
| ccx 2.23 gives an isotropic section the same results on any orientation axes, but prints its element stresses in them (NaN on zero axes: a spherical system written as rectangular, centred at the origin); its `*DEFORMATION PLASTICITY` depends on the axes (CalculiX issue #160) | writes a spherical orientation as the global axes where only isotropic sections read it; flags a spherical system and a cylindrical one's dropped rotation only where a section's results depend on them; writes the sections and plies of a `*DEFORMATION PLASTICITY` material without their orientation (reduced physics where another option of the material depends on the axes) | probed on `C3D8`, `C3D8I`, `C3D8R`, `C3D20R`, `S4R`, `M3D4`: elastic, NLGEOM, `*PLASTIC`, Neo-Hooke, `*CREEP`, `*EXPANSION` exact on turned and global axes; deformation plasticity up to 84 % off turned, a hang on zero axes; `validate_with_ccx.py sphere_hoop_*_iso`, `deformation_plasticity_*` |
| Abaqus gives initial stresses and plastic strains in the axes of the element's orientation, in the element type's order (plane stress: 11, 22, 12), strains with engineering shear; ccx 2.23 reads xx, yy, zz, xy, xz, yz in global axes, a plastic strain's shear as tensor components | turns such values into global axes — once per element on a rectangular system, at each of ccx's integration points on a cylindrical or spherical one — in ccx's order and shear measure; a continuum shell's components 11, 22, 12 out of its shell axes (with or without an orientation: the orientation projected, else global X; 3 the stack direction; a ply's turned by its angle) once per element or ply solid; reduced physics where the axes are not known (or off a plane element's plane); `REBAR` and `SECTION POINTS` records and a `*SHELL GENERAL SECTION`'s section forces left out | Keywords `*INITIAL CONDITIONS`; Conventions (Abaqus reports engineering shear strains; no page states the measure for this input); "Continuum shell element library" (S11, S22, S12); probed (a free cube; `C3D8I` / `C3D6` read global axes; `*EL PRINT, COORD` for the points); `validate_with_ccx.py initial_*` (before: 158 % off on a turned cube, 130 % on an annulus, 55 % on a tilted `SC8R` plate) |
| Abaqus orients a plain continuum-shell section as a shell: material axis 3 is the stack direction, axes 1 and 2 are the orientation projected onto the mid-surface (without one, global X projected), taken at its one in-plane integration point; ccx 2.23 gives the section's `C3D8I`/`C3D6` solids the orientation's axes unprojected (the global axes without one), a cylindrical system's at each integration point | keeps the `*SOLID SECTION`'s orientation where the two agree; elsewhere gives an orthotropic or anisotropic section Abaqus' axes per element through a `*DISTRIBUTION` (one `*ORIENTATION` where all share them) | Abaqus 2017 "About shell elements", "Continuum shell element library"; probed (`C3D8I`/`C3D6` patches under six uniform strains; a hoop-wound `SC8R` cylinder 14× too soft before); `validate_with_ccx.py sc_axes_*`, `sc_cylinder_hoop`, `sphere_hoop_sc8r*` |
| ccx has no incompatible-mode plane element. Its `CPS4` is a `C3D8` slab whose expanded nodes follow the 2-D node in plane with the thickness free (not 2-D plane stress: 0.3–3.6 % off a plane-stress Q4); its `CPE4` a plain 2×2 Q4. A `C3D8I` slab with DOF 3 held reproduces Abaqus' four-mode `CPS4I`/`CPE4I` (Simo–Rifai's form of Wilson's / Taylor's modes): in plane strain with the deck's material, in plane stress with an `ORTHO` material that has the plane-stress stiffness and no thickness coupling | writes `CPS4I`/`CPE4I` as one-element-thick `C3D8I` slabs (top nodes tied by `*EQUATION`, DOF 3 held: `ABQ2CCX_SLAB`) for small-strain linear elasticity in static steps and (`CPE4I`, whose fifth volumetric mode acts only off a parallelogram) parallelogram elements; otherwise `CPS4`/`CPE4`, as reduced physics | probed against a 2-D four-mode element: 1e-7 for ν 0, 0.3, 0.45 on rectangular and skewed meshes (a free-thickness slab: 0.06 % / 3 % off); Abaqus 2017 "Continuum elements with incompatible modes"; `validate_with_ccx.py cps4i_slab` |
| Abaqus' fully integrated first-order elements (`CPS4`, `CPE4`, `CAX4`, `C3D8`) replace the volume change at the Gauss points by the element average ("B-bar"); ccx's do not, and Abaqus' hybrid `CPE4H`/`C3D8H` (constant pressure) equal that B-bar element | runs a hybrid element as ccx's plain one only as reduced physics; the native elements carry the same difference (a 10 × 2 plane-strain cantilever: Abaqus deflects 9 % more at ν = 0, 19 % at 0.3, 3× at 0.49) | Abaqus 2017 "Solid isoparametric quadrilaterals and hexahedra"; probed (ccx `CPE4` = plain Q4 to 1e-8) |
| Abaqus documents `S3` and `S3R` as the same element; `STRI3` is a thin-shell facet element; `CPS6M`/`CPE6M`/`C3D10M` are "modified" elements with their own interpolation and hourglass control; `C3D10HS` has an 11-point scheme and switchable pressure DOFs; `CPE3H`'s constant pressure equals `CPE3` for a compressible material | `S3R → S3`, `CPE3H → CPE3` exact (a note); the other substitutions are reduced physics | Abaqus 2017 shell, 2-D and 3-D solid element libraries, "Solid (continuum) elements" |
| `*SECTION CONTROLS` changes the formulation only where its options apply: hourglass control on first-order reduced-integration and modified elements, element deletion / degradation / viscosity with progressive damage, distortion control on `C3D10HS`, and Explicit-only options (`SECOND ORDER ACCURACY` is "always second-order accurate in Abaqus/Standard"); the default `HOURGLASS` (`STIFFNESS` in Abaqus/Standard, `ENHANCED` on hyperelastic materials and modified elements), data-line factors of 1, and the Explicit-only out-of-plane, bulk-viscosity and drill factors change nothing | comments it out — a note where nothing applies, reduced physics otherwise | Abaqus 2017 Keywords `*SECTION CONTROLS` |
| ccx's `*SHELL SECTION` `OFFSET` takes only a number, which it reads as Abaqus does (0.5: the shell below its nodes) | `SPOS` → 0.5, `SNEG` → −0.5 | probed (expanded node coordinates) |
| ccx has no surface element (`SFM3D*`, `SFMAX*`, `SFMGAX*`); in Abaqus they have no stiffness and carry loads, mass or rebar | leaves them out of the mesh and applies their loads as nodal forces; keeps them, with a warning, if they carry rebar or mass that acts (unless `--approximate`) | Abaqus "Surface elements"; probed |

| Shells and membranes the same way in Abaqus. | Abaqus applies a shell's or membrane's pressure to its reference surface; ccx 2.23 to one face of the expanded solid — on a shell every label to the bottom face, whose area is off by O(t/R) ((1 − t/2R)² on a sphere), leaving a mean stress −p/2 through the thickness (Abaqus: plane stress). | ccx 2.23 expands each membrane element into a solid on nodes of its own, held at the membrane node by the mean of its top and bottom nodes; a quadratic element's mid-thickness corner node stays free (tied only at a node with a BC and a single element): `M3D8R` is singular in any mesh of two or more elements, `M3D6` several times too soft, `M3D8` too soft in thick elements | writes `M3D6` / `M3D8` / `M3D8R` as the `C3D15` / `C3D20` / `C3D20R` ccx would make, on nodes held by `*EQUATION` (bottom + top = 2 × node, mid-thickness corner node = node, per `C3D20R` one equation for its zero-energy hourglass); `M3D9` / `M3D9R` the same without the centre node (reduced physics); a `*TIE` slave (also a tied `*CONTACT PAIR`'s), a kinematic coupling's surface or a `*RIGID BODY` `ELSET` on them → the membrane nodes, which Abaqus uses (ccx would take the solids' nodes the equations eliminate); output at the membrane nodes → `*NODE PRINT` | sources `gen3dnor.f`, `gen3dmembrane.f`, `gen3dboun.f`; probed; `validate_with_ccx.py quad_membrane_*` |

## Materials

| Fact | What the converter does | Evidence |
| --- | --- | --- |
| `*ELASTIC` constants come in the same order; only the `TYPE` token differs | renames `ORTHOTROPIC` → `ORTHO`, `ANISOTROPIC` → `ANISO` | ccx manual |
| `*EXPANSION, TYPE=ANISO`: Abaqus' α12, α13, α23 are engineering shear (γ12 = α12 ΔT), ccx's are tensor components (ε12 = α12 ΔT) | halves them on every temperature row (a NOTE per material) | probed in ccx; Abaqus: Conventions, the `UEXPAN`/`UMAT` strain arrays, the PZT-5H verification `ppzovallin.inp`, and an Abaqus run in `wenbinyugroup/sgio` |
| In linear steps of a deck with temperatures, ccx 2.23 uses a wrong stiffness when the `*ELASTIC` is less anisotropic than the `*EXPANSION` (isotropic beside ORTHO/ANISO: a heated free cube shrinks, frequencies come out 17× low; orthotropic beside ANISO without an orientation: spurious shear strains) | writes the `*ELASTIC` as `ENGINEERING CONSTANTS` or `ANISO` with the same stiffness, adding temperature rows so the interpolation matches Abaqus' | probed on solids, shells, membranes, plane elements, beams and trusses; sources `linel`, `materialdata_me`, `elastics`; `validate_with_ccx.py thermal_expansion_cubes`, `thermal_expansion_elastic_forms` |
| Under NLGEOM, ccx 2.23 treats an ORTHO expansion as diagonal in global axes (the shear of turned material axes is lost) and stops an ANISO one with "too many cutbacks" | writes a zero-shear ANISO expansion as ORTHO where no orientation turns it; warns about the rest | probed; sources `calcmechstrain`, `modifystressstiff` (fixed in the CalculiX sources after 2.23, October 2026) |
| Reading `*DEFORMATION PLASTICITY` (even unused), ccx 2.23 runs the whole model under NLGEOM, the law in the logarithmic strain and the Cauchy stress; with an explicit `NLGEOM=NO` it reads the small strain as a Green-Lagrange one (a pure shear strain then gives a pressure). Abaqus takes the small strain without NLGEOM | flags small-strain steps with the law as reduced physics; drops `NLGEOM=NO` there; comments out a material of the law that nothing uses | probed (homogeneously deformed `C3D8`: uniaxial, shear, turned; a bar in tension 0.39 % past Abaqus at σ0, 12 % at 2σ0; 32 % with `NLGEOM=NO`); Abaqus 2017 Theory and Materials "Deformation plasticity"; `validate_with_ccx.py deformation_plasticity_small_strain*` |
| ccx's Johnson-Cook plasticity switches on only with a `*RATE DEPENDENT, TYPE=JOHNSON COOK` card; ccx silently skips `*PLASTIC` forms it lacks | adds a rate-independent card (C = 0) when the deck has none; comments `HARDENING=USER` and Chaboche `PARAMETERS` out (the material runs elastic, warned) | probed |
| ccx ignores `DEPENDENCIES=` and in effect uses the first row | collapses the table to field = 0, Abaqus' no-field state: that state's rows, the end of the table nearest 0 (Abaqus holds it beyond the table), or the interpolation between the two states around 0 when they share their temperatures — exact when the deck sets no field variable; reduced physics otherwise | probed |

## Version notes

* Written for CalculiX 2.22–2.23 and validated on **2.23**, the build in FreeCAD 1.1.4. There
  is no 2.24 as of October 2026.
* ccx 2.23 segfaults where a card it rejects (step data outside a `*STEP`, a section naming
  an undefined material) is the deck's last card and has a data line (CalculiX PR #190), and
  builds without the fix of PR #200 crash on DOFs 4–6 of plane-element nodes; the converter
  comments, warns about or drops them. 2.23 rejects rigid constraints on shell and beam nodes,
  hence the knot beams.
* The CalculiX sources fixed the NLGEOM thermal-expansion problems after 2.23 (October 2026);
  a build with the fix was not tried.
* Older versions gate some cards: `*MEMBRANE SECTION` from 2.14, the `*ORIENTATION` rotation
  line from about 2.15, `C3D8R` hourglass control from 2.3.

## What does not convert or solve

Abaqus has about 570 keywords and CalculiX about 140, so "unsupported keyword" is expected
for any non-trivial deck. The converter classifies every keyword — translated, dropped as
organisational, or commented with guidance — and the [keyword reference](keyword-reference.md)
gives the full split.

Of the 1052 corpus decks, 599 do not solve; most need what stock ccx does not have: user
materials (353 decks), user elements (66), and other user subroutines, Riks, explicit coupled
temperature–displacement steps, cohesive and acoustic models, Abaqus general contact. Others are
incomplete source decks (50). Another 31 solve only a model with reduced physics — the
conversion had to drop or replace part of it (concrete damaged plasticity, user hardening,
Chaboche back-stresses, field-dependent properties, hybrid / modified / thin-shell elements,
Euler–Bernoulli `U1` beams for Timoshenko ones, general contact, an imperfection), and one converges to a solution that is not the deck's (a
body that only contact holds drifts away before the contact closes) — all kept out of the
count of faithful solves. The
[testing page](testing.md#3-corpus--corpus-and-teststest_corpuspy) breaks them down. Fixing a first error often only exposes a second, fundamental one, so the
converter translates or clearly flags each incompatibility rather than forcing a deck to run.

**If your converted deck won't solve,** read the first `*ERROR` ccx prints. A missing
capability or an incomplete deck needs remodelling (replace a UMAT with a built-in material,
write general contact as contact pairs, add the missing step, refine an inverted element),
not a different conversion. The report at the top of the converted deck lists the cards that
were approximated or commented out; [troubleshooting](troubleshooting.md) covers the common
errors.

## What "verified" means

Each fact comes from a primary source and, where possible, a second one: the
`calculix/new_keywords` and `calculix/cae` keyword lists, the community conversion guide, an
existing importer (`gmsh2ccx`, FreeCAD, PrePoMax), or a probe. Two facts rest on indirect
evidence: the midside edge-node sequence, which the manuals show only in figures (it is the
universal Abaqus/Gmsh convention, and `gmsh2ccx` passes it through unpermuted), and the
engineering shear measure of `*EXPANSION, TYPE=ANISO`, which no Abaqus page states in words
(four sources agree; a free unit cube with α12 ≠ 0 in Abaqus would settle it).
